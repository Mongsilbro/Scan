# 스캔 PDF 페이지 찾기

스캔한 PDF에서 찾는 내용이 **몇 쪽에, 그 쪽의 어디에** 있는지 알려주는 도구입니다. HTML 파일 하나로 동작하고 **인터넷 연결이 필요 없습니다.** PDF는 컴퓨터 밖으로 나가지 않습니다.

## 쓰는 법

1. [`dist/pdf-page-finder.html`](dist/pdf-page-finder.html)을 내려받아 크롬이나 엣지로 엽니다.
2. PDF를 끌어다 놓고, 찾을 내용을 입력합니다.
3. 쪽 번호를 누르면 미리보기에 찾은 위치가 노란 상자로 표시됩니다.

- **2단계 판독**: 1차 판독(빠른 엔진)이 끝나면 바로 검색할 수 있고, 2차 판독(신경망 엔진)이 이어서 결과를 보강합니다. "정밀 판독"을 끄면 1차만 해서 약 2배 빠릅니다.
- **그래픽카드 사용**: 크롬·엣지에서 그래픽카드(WebGPU)가 보이면 CPU와 함께 2차 판독에 씁니다. CPU보다 느리거나 오류가 나면 자동으로 빼고 CPU로 계속합니다. 끝나면 "그래픽카드가 글줄 N% 판독"이라고 표시됩니다. 주소 뒤에 `?gpu=0`을 붙이면 끕니다.
- **여러 파일**: PDF 여러 개를 한꺼번에 고르거나 끌어다 놓으면 차례로 분석하고, 모든 파일에서 찾아 파일별로 보여줍니다. 파일마다 "글자 저장"으로 인식된 글자를 텍스트 파일로 받을 수 있습니다.
- **여러 낱말**: 쉼표로 나누면(예: `계약 기간, 손해배상`) 낱말마다 따로 찾고, 모두 들어 있는 쪽도 보여줍니다. 숫자 안의 쉼표(86,573)는 나누지 않습니다.
- **검색 기호**: `"손해 배상"`처럼 따옴표로 감싸면 정확히 같은 것만, `-계약기간`처럼 앞에 -를 붙이면 그 말이 있는 쪽은 뺍니다. 미리보기에서는 찾은 말마다 다른 색 상자로 보여줍니다.
- **찾은 곳 그림**: 검색 결과마다 찾은 줄 둘레를 스캔 그림 그대로 잘라 보여 줍니다(표라면 같은 행의 금액까지). 화면에 보이는 결과만 그리고, 누르면 미리보기가 열립니다. "찾은 곳 그림 보기"를 끄면 글자만 보입니다.
- **미리보기**: ◀ 이전 / 다음 ▶ 버튼이나 ← → 키로 다음 결과로, ◀쪽 / 쪽▶ 이나 PageUp / PageDown 으로 앞뒤 쪽으로 넘어갑니다. − / 맞춤 / + (키 −, 0, +)로 확대합니다.
- **결과 활용**: "결과 복사"(쪽 번호), "엑셀로 저장"(파일·쪽·찾은 부분을 CSV로), "모든 파일 글자 저장"(ZIP). 체크 상자 설정과 최근 검색어 10개는 이 브라우저에 기억됩니다. `/` 키로 검색창에 바로 갑니다.
- **검색되는 PDF로 저장**: 파일 목록의 "검색되는 PDF"를 누르면, 스캔 그림은 그대로 두고 인식된 글자를 투명하게 넣은 PDF를 저장합니다. 크롬·엣지·아크로뱃·한글 등 어느 PDF 보기 프로그램에서든 Ctrl+F로 찾고 글자를 복사할 수 있습니다. 옆으로 눕거나 뒤집힌 쪽은 바로 세워서 저장합니다.
- **고른 쪽만 새 PDF로**: 파일 목록의 "쪽 저장", 검색 결과의 "찾은 쪽 저장", 미리보기의 "이 쪽 저장"에서 `2, 5-7, 12`처럼 적어 저장합니다. 쉼표로 나눈 묶음(구역)을 한 PDF로 합치거나, 구역마다 따로 PDF로 만들어 ZIP 하나로 받을 수 있습니다.
- **이전에 분석한 파일**: "이전에 분석한 파일 불러오기"를 누르면 이 브라우저에 저장된 결과(최근 30개)를 목록에 올려 원본 PDF 없이도 찾습니다. 미리보기는 인식된 글자로 보여 주고, 원본을 다시 넣으면 그림과 위치 표시가 나옵니다.
- **결과 저장**: 한 번 분석한 파일은 브라우저에 결과가 저장되어, 다시 열면 바로 검색됩니다(최근 30개). "저장된 결과 지우기"로 지울 수 있습니다.
- **검색 방식**: 띄어쓰기·문장부호·영문 대소문자는 무시합니다. 글자가 조금 틀리게 인식된 비슷한 표현도 찾고, 이런 결과는 점선과 `?`로 구분해 보여줍니다.

## 구조

| 경로 | 내용 |
|---|---|
| `src/head.html` | 화면(HTML·CSS) 바탕. 빌드할 때 `tools/build.py`가 일부를 고쳐 씁니다 |
| `src/main.js` | 전체 동작: PDF 읽기, 전처리, 표 칸 찾기, 글줄 찾기, 두 엔진 판독, 검색, 위치 표시, 결과 저장 |
| `src/recworker.js` | 신경망 판독 작업자(onnxruntime-web) |
| `src/imgproc.js`, `src/prepworker.js` | 그림 처리 함수(전처리·표/글줄 찾기·글줄 자르기)와, 그 일을 화면 쪽 대신 하는 준비 작업자 |
| `models/` | 내장 모델과 라이선스 (아래 표) |
| `tools/build.py` | 라이브러리·모델을 모두 넣어 `dist/pdf-page-finder.html` 하나로 묶음. 같은 입력이면 같은 결과 |
| `tools/prune_model.py` | 신경망 모델 경량화에 쓴 스크립트 |
| `tools/dequant_matmul.py`, `tools/split_external.py` | 그래픽카드용 실수 모델 만들기, 두 모델이 함께 쓰는 가중치(`rec_w.bin`) 나누기 |
| `tools/make_glyphless.py` | 검색되는 PDF의 숨은 글자용 작은 글꼴(`models/glyphless.ttf`) 만들기 |
| `tools/fold_affine.py` | 모델의 배율·더하기 층을 합성곱에 합치는 스크립트(결과 같고 더 빠름). `models/rec_small_int8.onnx`에 적용됨 |
| `tests/regress.js` | 회귀 테스트: 네트워크를 막은 브라우저에서 쪽 찾기·위치 표시·결과 저장 확인 |
| `tests/a11y.js` | 접근성 시험: axe-core로 주요 화면을 WCAG 2.2 AA 기준 점검(시험에만 씀) |
| `tests/offline.js` | 오프라인 시험: 인터넷을 끊은 브라우저에서 모든 기능(분석·여러 파일·검색·미리보기·복사·쪽 저장·글자 저장·다시 불러오기, 그래픽카드 판독 포함)을 써 보고 바깥 요청이 0건인지 확인 |
| `tests/bench.js` | 성능 측정: 시간, 키워드 적중률, 글자 정확도 |
| `tests/gen_*.js`, `tests/fixtures/` | 시험용 스캔 PDF와 그 생성기 |

## 빌드와 테스트

```bash
npm ci
```

```bash
python3 tools/build.py
```

```bash
node tests/regress.js dist/pdf-page-finder.html
```

```bash
node tests/offline.js dist/pdf-page-finder.html
```

```bash
node tests/a11y.js dist/pdf-page-finder.html
```

```bash
T=table2 node tests/bench.js dist/pdf-page-finder.html
```

테스트에는 Playwright와 Chromium이 필요합니다(`require('playwright')`). `T`는 `table2`(굵은 고딕 표 6쪽) 또는 `hard2`(명조 2단 편집 8쪽)입니다.

## 측정 결과 (4코어, 2026-11-19)

| 시험 문서 | 찾은 키워드 | 글자 정확도 | 걸린 시간 |
|---|---|---|---|
| 표 문서 6쪽 (`table2`) | 84/84 | 97.7% | 약 16~17초 (1차 결과 약 9초) |
| 2단 문서 8쪽 (`hard2`) | 44~45/48 | 96.0% | 약 21~22초 (1차 결과 약 9~10초) |

못 찾는 3~4개는 일부러 가장 흐리게 만든 쪽의 작은 각주에 있습니다.
